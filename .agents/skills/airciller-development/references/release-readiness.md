# Release readiness

[DISTRIBUTION.md](../../../../DISTRIBUTION.md#release-procedure) owns signing, packaging, upload and update commands. Use it when the requested task reaches that stage. A readiness review reports existing evidence and gaps; it does not itself authorize version bumps, uploads, installation or merging main.

Assess each applicable stage separately:

1. **Code acceptance:** required [contribution checks](../../../../CONTRIBUTING.md#minimum-validation) pass for the candidate. For playback changes, use [playback evidence](playback.md) and complete the applicable [TESTING matrix](../../../../TESTING.md#3-physical-apple-tv-matrix) before publication/installation, including stop, replay and app close. Missing required observations block that gate. Preserve candidate identity when carrying evidence forward: compare changed playback source, locked runtimes and relevant build configuration; metadata-only changes do not turn earlier observations into new device runs.
2. **Release content:** derive versions from current files and reconcile the release diff with [CHANGELOG.md](../../../../CHANGELOG.md), versioned notes and affected compatibility/roadmap records. Follow [the release-note template](../../../../Distribution/ReleaseNotes/TEMPLATE.md) for usage, supported scope and evidence-linked limitations. Documentation/agent-instruction-only work needs no binary version bump.
3. **Distribution:** validate the intended signing configuration, pinned runtime, bundle size, preserved third-party signatures, archive and signed Sparkle feed under DISTRIBUTION. A passing development build does not certify the public package. Local certificate/ad hoc signing is not notarization. Do not hand-edit signed feeds or replace historical assets for prose corrections.
4. **Publication:** require conversation authorization and the preceding applicable gates. Check CI for the exact candidate commit; after an authorized tag, separately verify its tag-triggered CI. Inspect failures and retain failed attempts; pending/failed required CI is not completion. Verify published asset URLs, signatures and release prose against the reviewed package and notes.
5. **Installation/update:** require authorization, preserve a rollback copy and verify the actual update, relaunch and installed version as specified in DISTRIBUTION. A published archive or a prepared installation command is not a completed installation.

Report only the stages actually established: code accepted, playback validated, packaged, published or installed, with remaining gaps. A documentation PR can be ready for review without attempting a binary release. Never inherit release readiness from a dated report or a green run for a different commit without explaining which evidence remains applicable.

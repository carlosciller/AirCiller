# aiohttp maintenance candidate

19 October 2026. Based on main `d7cb4bd`; this is a preparation branch for
PR #29, not a published or installed update. The version remains 0.17.1 until
an authorized release task assigns the next patch version and build.

## Scope and compatibility

- aiohttp 3.14.3 becomes 3.14.5. The upstream
  [resource-exhaustion advisory](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-2g87-pp6c-29x5)
  and [connection-pool advisory](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-6cjc-53gc-5rqm)
  list versions through 3.14.3 as affected and 3.14.4 as patched. This is not
  evidence of an exploit against AirCiller.
- pyatv 0.18.0 declares `aiohttp>=3.8.3,<5`; 3.14.5 satisfies that range.
- aiohttp 3.14.5 requires `yarl>=1.25.1,<2.0`. The regenerated lock therefore
  changes yarl 1.24.5 to 1.25.1. No other locked package version changes.
- zeroconf, protobuf, pyatv, Python, FFmpeg and Sparkle remain pinned. No packager,
  subtitle/timing behavior, conversion policy, credential store or interface changes.

The lock is generated by `Scripts/requirements_lock.sh update` using the existing
pinned compiler. The initially reported yarl conflict is resolved by selecting
the newly required minimum, not by an unrestricted dependency upgrade.

## Actual callers and validation selection

`Scripts/airplay_helper.py` calls `pyatv.scan` and `pyatv.pair`.
`pyatv.pair` creates an aiohttp ClientSession through
`pyatv.support.http.create_session`; its AirPlay handler owns and closes it.
The pairing handshake itself uses pyatv's `HttpConnection`.

Normal `play_command` and `authorize_command` use pyatv's `http_connect`,
HAP verification and RTSP/event channels, not aiohttp ClientSession requests or
WebSockets. The local movie server is the native Swift HTTP server, not
`aiohttp.web`. Both prepared-media routes share those unchanged connections.
`yarl` is still imported by the dependency graph; its new URL behavior is included
in the compatibility checks. Do not infer a new media capability or performance
gain from this dependency change.

Required checks for this boundary:

1. Regenerate/check the lock and compare every locked package version.
2. Validate installed dependency requirements and import the real locked modules.
3. Exercise real pyatv/aiohttp ownership, borrowed sessions, pairing-handler close,
   factory failure, cancelled PIN waiting, failed begin and invalid PIN. Network
   connections are forbidden; no real PIN, credential or receiver is accessed.
   Tests assert closed sessions/connectors, no surviving tasks or unhandled errors.
4. Run `Scripts/check.sh` once on the final executable inputs, including strict
   Swift compilation, helper simulations, packaging, signatures and size.
5. Repeat the focused compatibility tests and import/path checks using the
   candidate's bundled Python and VendorPython, and inspect distribution findings.
6. Require successful CI for the exact reviewed PR head before review handoff.

No new Apple TV session is selected: media preparation, serving, video transport,
remote commands and engine binaries are unchanged. This deliberately carries
forward their existing evidence. It does not claim fresh HDR/subtitle output.
Long pauses, OCR, cache campaigns and physical speaker checks are not selected.
Reassess only if the diff or actual caller investigation changes that boundary.

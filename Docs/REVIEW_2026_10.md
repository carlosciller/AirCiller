## Private-control corrections

- Relay completion now normalizes an operation UUID before both lookup and
  removal. Completing with lowercase previously retained the uppercase entry,
  eventually exhausting queue capacity. The regression uses a one-entry queue
  and confirms that the next command can be admitted.
- Lifecycle status calls no longer consume the mutation ledger. More than
  1,024 queries still return current state. Mutations remain bounded and retain
  failed/disabled outcomes; concurrent duplicates execute once, while changed
  action/session reuse and a full ledger return explicit errors.
- Lifecycle commands require a plain object and empty object arguments. Arrays,
  null and primitive payloads no longer masquerade as valid empty arguments.
- The native app validates the relay operation ID against the authenticated
  envelope before dispatch. The previous check happened after mutation. A
  mismatched authenticated Stop now leaves the active control session intact.
- Untimed receiver observations retain an absent position. UI ticks and command
  acknowledgements cannot create fresh receiver evidence or a fabricated zero.

The lifecycle HTTPS fixture uses a temporary localhost certificate and an actual
server. Correct pin/hostname requests and keep-alive reuse pass; incorrect pin
or hostname is rejected before any credential-bearing HTTP request. Redirects
are not followed. No production secret or relay was used by these tests.

These source changes do not update the installed relay or lifecycle LaunchAgent.
Deployment is separate from building the app. The current runtime still has a
bounded 1,024-mutation lifetime ledger, and large library-search results need a
future bounded/paginated contract. Those are explicit remaining constraints,
not permission to evict uncertain mutations and replay them.

Review also covers preparation, HTTP, credentials, persisted data, subtitles,
updater/distribution, performance and native presentation. Further findings must
identify a reproduction or be labelled hypotheses before being selected.

The final code candidate requires `Scripts/check.sh` once, plus changed native
interactions. Shared-control changes require assessing both video routes; existing
format evidence can be carried forward only after comparing its inputs. The
installed private open/close workflow passed the current locked-session check

## Performance baseline

The retained October startup measurements separate local preparation, HTTP and
receiver events. Their capture gaps do not prove continuous audiovisual onset.
The maintainer subsequently reported that the Apple TV uses Wi-Fi 6; this is a
user report, not a readout of the receiver's network settings.

The approximately 3.3-second accepted-to-playing interval is not an established
removable delay. Review redundant local work before proposing changes to session
reuse or segmentation. New before/after claims require comparable inputs.

A new three-repeat small-fixture baseline completed with exact served-output
parity against committed `6841059`. No-cache medians changed from 28.709 to
26.385 ms for SubRip and 24.731 to 28.076 ms for ASS. Ranges overlap and direction
differs, so no speed improvement or regression is claimed. Existing warm-cache
reuse measured about 14.7-14.9 ms. These numbers exclude probing and do not
measure first television image/audio. See the playback review for sample identity,
retained negative historical comparison and scope.

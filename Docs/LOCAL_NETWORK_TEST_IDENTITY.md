## Prevention

Auxiliary builds reject missing or ad hoc signing configuration. The staging
helper requires a valid Apple-issued signature and stable designated requirement,
uses one destination across worktrees and refuses replacement of a running app.
It verifies a copied bundle before replacing the previous verified copy. The
capture and control launchers use that destination; UI candidates must do so too.
Ordinary release signing and the daily credential service remain unchanged.

Five staging regressions cover reuse/replacement, identity mismatch, unsigned
input, running-app refusal, failed copied verification and symlink destinations.
All 35 capture workflow tests passed without weakening their existing assertions.
The archived UUID-named coordinator-test records had no explicit multicast
permission and were not the visible clutter; test isolation remains unchanged.

Apple recommends an Apple-issued identity for reliable Local Network tracking:
[TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).
The earlier self-signed test bundle was rejected by staging; no signature check
was relaxed. The existing Apple-issued certificate and a separate ignored local
credential-service build were used only after the maintainer's authorization.
No certificate was created, no original service rebuilt, no system privacy
archive edited and no unrelated permission reset.
